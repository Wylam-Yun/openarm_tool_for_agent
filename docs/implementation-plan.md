## 候选与决定
1. 延续纯TCP位置补偿：改动小，但姿态偏差不可处理。
2. SE(3)位置/姿态补偿：保持位姿接口，但关节补偿范围难直接约束。
3. 固定IK关节目标 + 实测稳态偏差前馈 + 限幅纠偏：多一次只读IK请求，可逐关节约束与观测。采用此方案，保留公开能力与MoveIt执行接口。
驱动增益/重力补偿不在用户允许范围。

只接受稳定且新鲜的控制器反馈；补偿上限0.30rad，单轮追加最多0.08rad，目标关节变化最多0.45rad（复位亦同）；MoveIt拒绝即停止。下降和move_delta不自动重复纠偏。目标值整个动作保持固定。现有TCP补偿不与关节补偿叠加。

### 待确认的执行链变更
A（推荐）：MoveIt仍负责IK和完整真实关节路径规划；skill将每个轨迹点加上受限负载偏差，从当前holding_command严格连续起步，调用现有FollowJointTrajectory action执行。真实目标不变，逐时采集外部反馈，检查起步下坠、偏差与返回码。代价：skill承担轨迹变换、执行监控和取消责任。
B：skill提供独立重力/阻抗控制器。代价：需动力学模型、控制器切换和更多验证，改动显著，不选。
C：保留当前MoveGroup执行，停止自动抓取。代价：无法在skill内保证起步连续，用户任务无法完成。
RBM项目、驱动与其配置保持原样。A需要明确确认，因为用户AGENTS要求架构层偏离必须问。

### A的可审查算法与验收
1. 记录稳定新鲜实际q0和当前控制目标u0；b0=u0-q0，只支持有界偏差。
2. 固定目标q*，MoveIt只读规划q0→q*；拒绝首点不一致、越界、过大关节绕行、规划错误。
3. 对整轨迹构造u(t)=q(t)+b(t)。b(0)=b0，故u(0)=u0；纠偏末端b1以零端点速度/加速度的平滑曲线变化。不把偏差加到真实目标定义中。
4. 与既有轨迹控制器action连接，逐样本验证起步无卸力跳变，并监控真实TCP未向反方向越过允许余量；异常取消并保持最近连续目标，绝不断电或自动reset。
5. 每次动作终态必须真实关节/TF和外部返回码均通过；下降禁止反复积分补偿。
6. 先做20mm自由空间抬升，独立ROS/CAN时间序列与相机证明起步不下坠，再恢复抓取。

## 用户关于刚度的补充
增大电机Kp可减小负载稳态偏差，但现有驱动Kp在RBM硬件插件编译常量里（大关节约20、腕部约5，CAN只读抓包一致），用户已明确不修改RBM。也不能通过改skill的位置容差伪装成刚度变化。整轨补偿不改变电机刚度，解决的是控制目标起步跳变；机械标定偏差仍需外部图像/测量验收。

实测恢复时关节4稳定支撑偏差达0.319rad，原0.30上限在发送下一动作前拒绝。补偿上限改为0.40rad（现有Kp=20对应最多8Nm位置项；腕部Kp=5最多2Nm），保留每轮0.08rad增量限幅、模型关节限位、原目标误差验收。不提高电机Kp，不关闭控制器误差检查。控制器命令空间容差按最大支撑偏差+0.10rad跟踪余量设置，避免把正常支撑偏差误判为路径失控。
